==================================================
PROJECT OVERVIEW
==================================================

The project monitors the condition of stored fruit using a Bosch BME688 gas sensor connected to an ESP32.

The system collects environmental and gas-related sensor data. The collected data will be used to train a machine-learning classification model that can classify fruit condition into categories such as:

- FRESH
- RIPE
- SPOILED

The trained prediction algorithm will eventually run with the ESP32/BSEC system so that a new fruit/batch can be tested and its condition predicted.

The project is NOT only a fruit-prediction system. It is a MULTI-AGENT SYSTEM consisting of:

1. Sensing Agent
2. Forecasting Agent
3. Logistics Agent
4. Negotiator Agent

There will also be a web dashboard through which the user can monitor the system and visualize predictions, logistics decisions, routes, stores, etc.

==================================================
AGENTS
==================================================

1. SENSING AGENT
----------------

Hardware:
- ESP32 DevKit V1
- Bosch BME688
- BSEC library
- SD card module

Responsibilities:
- Collect sensor readings
- Monitor gas-related measurements
- Monitor temperature, humidity, pressure, etc.
- Log measurements to SD card
- Provide sensor data to the rest of the system

This portion is being handled by me.

The current ESP32 system wakes up periodically, activates the sensor for approximately 5 minutes, logs data, and then goes into deep sleep before the next cycle.

The exact CSV format and AI-Studio compatibility will be verified later before the final dataset/model training.

--------------------------------------------------

2. FORECASTING AGENT
--------------------

Responsibilities:
- Use BME688 sensor data
- Train a classification model
- Classify fruit condition
- Eventually run the trained model on/alongside the ESP32/BSEC system
- Produce a prediction such as:

  FRESH
  RIPE
  SPOILED

It may also provide a confidence/probability value and potentially an estimated remaining shelf life.

Example output:

{
  "fruit_id": "F001",
  "condition": "RIPE",
  "confidence": 0.87,
  "remaining_shelf_life_days": 3
}

The exact fields will be finalized later.

The model training and deployment are being handled by me.

--------------------------------------------------

3. LOGISTICS AGENT
------------------

The Logistics Agent takes the fruit prediction and determines what should happen with the batch.

Example:

Forecasting Agent:
"Batch A is RIPE and has approximately 3 days remaining."

Logistics Agent:
"This batch should be dispatched soon. Find a suitable destination."

The Logistics Agent should consider factors such as:
- Fruit condition
- Remaining shelf life
- Store distance
- Store demand/capacity
- Available transport
- Delivery time
- Priority of the batch

Do NOT reduce the Logistics Agent to simply "find the nearest store."

The goal is to determine a suitable destination and logistics decision.

--------------------------------------------------

4. NEGOTIATOR AGENT
-------------------

The Negotiator Agent works together with the Logistics Agent.

The project concept includes the Contract Net Protocol.

The Negotiator Agent can be responsible for:
- Checking available vehicles/resources
- Receiving/submitting bids or offers
- Comparing possible resources
- Selecting the most suitable vehicle/resource
- Helping finalize the delivery decision

Example:

Logistics Agent:
"Batch A must be delivered to Store B."

Negotiator Agent:
- Vehicle 1 available
- Vehicle 2 available
- Vehicle 3 unavailable

After negotiation:
"Vehicle 2 selected."

The exact negotiation logic can be simplified enough to be practical for a college project, but the system should demonstrate the concept of agent-to-agent negotiation.
